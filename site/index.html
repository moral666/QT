O caminho de uma mensagem

Passo 1 de 3

Fechada no teu telemóvel

Antes de sair, a mensagem é trancada com uma chave. Cada mensagem tem uma chave diferente.

Passo 2 de 3

Viaja sempre fechada

Passa pelo nosso servidor, que só a entrega. Não a consegue abrir nem sabe quem a enviou.

Passo 3 de 3

Abre só no destino

Só o telemóvel de quem a recebe tem a chave para a abrir.

Para especialistas

Para especialistas

Double Ratchet

Uma chave nova por mensagem, com sigilo futuro e recuperação depois de uma chave ser comprometida.

Para especialistas

PQXDH

Acordo de chaves híbrido: X25519 com ML-KEM-768. O X3DH clássico continua disponível.

Para especialistas

Remetente selado

O relay recebe envelopes cifrados sem saber quem os enviou (sealed sender).

Para especialistas

Ligação ao relay

WebSocket seguro (wss) com o protocolo Noise, e a chave do relay fixada na app.

Para especialistas

Armazenamento

SQLCipher, com a chave protegida pelo Android Keystore e secure_delete ativo.

Para especialistas

Núcleo em Rust

Toda a criptografia vive num só núcleo em Rust (core, ffi, storage). Nada é reimplementado nas apps.

Para especialistas

UniFFI

As apps chamam o núcleo por ligações geradas com UniFFI. No Android: arm64-v8a, armeabi-v7a e x86_64.
